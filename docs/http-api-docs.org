#+title: StarIntel HTTP API
#+options: toc:3

* HTTP API

Default base URL: =http://127.0.0.1:5000=.

The server uses API-key authentication by default. Public paths are deliberately
limited; authenticated routes require =Authorization: Bearer <api-key>= and are
subject to server authorization policy. CORS is allow-list based rather than
wildcard. See [[file:http-users.org][HTTP users and credentials]] for the human-user lifecycle.

All implemented routes are mounted at =/=; =*http-api-base-path*= is not used.

* Machine-readable contract

The first stable control-plane surface is described by one Common Lisp contract
registry shared by the server and =starintel-gserver-client=. The registry is the
source for route method/path metadata and generated client operation wrappers.

Two public discovery endpoints expose the contract:

- =GET /openapi.json= returns OpenAPI 3.1.2;
- =GET /client-manifest.json= returns the normalized StarIntel client manifest.

#+begin_src sh
curl --fail http://127.0.0.1:5000/openapi.json | jq
curl --fail http://127.0.0.1:5000/client-manifest.json | jq
#+end_src

The initial contracted operations cover:

- process health and server metadata;
- password login and authenticated-context inspection;
- human-user create/list/password lifecycle;
- API credential create/list/rotate/revoke/disable lifecycle;
- OpenAPI and client-manifest discovery.

Legacy document, target, search, and CouchDB-view routes remain available and
will migrate into the same registry incrementally. Clients should prefer named
SDK operations over hard-coded route strings where a contracted operation exists.

* Common request behavior

Authenticated requests use:

#+begin_src text
Authorization: Bearer star_sk_v1_...
#+end_src

The HTTP boundary also understands:

| Header | Purpose |
|--------+---------|
| =X-Correlation-ID= | Caller-supplied bounded correlation identifier |
| =X-Request-Timeout-Ms= | Bounded logical request timeout request |
| =Content-Type: application/json= | Required for JSON request bodies |
| =X-Star-Bootstrap-Secret= | Bootstrap-only secret for =/auth/bootstrap= |

Errors use client-safe JSON envelopes containing =status=, =msg=,
=correlation_id=, and usually a stable =code=. Server tracebacks and secrets are
not returned in normal error responses.

* Core endpoints

** GET /health

Process-level liveness. This does not deeply verify CouchDB, RabbitMQ, Valkey, or
Clouseau.

#+begin_src sh
curl --fail http://127.0.0.1:5000/health | jq
#+end_src

** GET /

Returns server metadata including document spec version, configured databases,
server version, and links to the machine-readable contract endpoints.

#+begin_src sh
curl --fail http://127.0.0.1:5000/ | jq
#+end_src

* Authentication and users

Public authentication routes include =POST /auth/login= and bootstrap when
configured. Administrator-authenticated routes manage users and API credentials.
The canonical route shapes and request/response schemas are emitted by
=/openapi.json=; operational examples live in [[file:http-users.org][http-users.org]].

* Legacy document and target endpoints

These routes predate the machine-readable registry and are retained for
compatibility while they are migrated.

| Method | Route | Purpose |
|--------+-------+---------|
| POST | =/new/document/:dtype= | Publish one document for ingestion |
| POST | =/documents/bulk= | Publish a bounded document batch |
| GET | =/document/:id= | Read one document |
| PUT | =/document/:id= | Update one document through the HTTP boundary |
| DELETE | =/document/:id= | Delete one document |
| POST | =/new/target/:actor= | Submit a target to an actor |
| GET | =/targets/:actor= | Read persisted targets for an actor |
| GET | =/search= | Full-text search |

Document write routes validate bounded JSON input, required StarIntel document
fields, and the supported document schema version before dispatch.

* View query routes

View-backed routes expose bounded pagination/query parameters. Common parameters
include =limit=, =start_key=, =end_key=, =descending=, =skip=, and route-specific
=reduce=. String start/end keys are JSON values and therefore need JSON quoting.

Representative routes include:

| Route | Key parameters |
|-------+----------------|
| =/documents/messages/by-user= | =user= |
| =/documents/messages/by-channel= | =group=, =channel= |
| =/documents/messages/by-platform= | =platform= |
| =/documents/messages/groups= | pagination parameters |
| =/documents/socialmpost/by-user= | =user= |
| =/documents/hosts/by-ip= | =ip= |
| =/documents/emails/by-email= | =email= |
| =/documents/domains/by-record= | =record= |
| =/documents/users/by-platform= | =platform= |
| =/documents/networks/by-asn= | =asn= |
| =/documents/urls/by-domain= | =domain= |

The historical =socialmpost= spelling is still part of the implemented legacy
wire path.

* Client generation boundary

=starintel-gserver-client= contains a handwritten runtime for transport,
authentication, timeouts, error normalization, correlation metadata, and secret
redaction. Thin request wrappers for contracted operations are generated from the
shared Lisp registry at compile/load time.

Generated wrappers call one runtime primitive and do not contain Dexador,
authentication, or retry policy. This keeps regeneration from overwriting client
semantics while still removing repetitive wire code.

* HTTP operational notes

- Authentication is enabled by default and may only be disabled through the
  explicit loopback development bypass.
- CORS origins are configuration allow-listed; wildcard origins are not emitted.
- Request bodies are bounded and parsed as JSON at the hardened HTTP boundary.
- Correlation identifiers are propagated in response headers and structured
  control-plane responses.
- The contracted API is emitted as OpenAPI 3.1.2 and a StarIntel client manifest.
- Legacy routes remain intentionally outside the initial generated-client
  guarantee until migrated into the registry.
