#+title: Embedded StarRouter acceptance evidence

* Scope and current status

This is the acceptance matrix for Server #193 / StarRouter #5. A native
transport check is not the complete Server target/document acceptance test.
RabbitMQ remains a parallel supported transport. SC01 compatibility and
=star.actor2actor/1= are separate profiles; neither implies document schema
version. The server schema lock remains authoritative.

* Required matrix

No row is satisfied by task admission, source inspection, a mock, a skipped
test, or successful transport send. Socket queue acceptance does not prove
durable storage. A possibly committed operation with a lost reply remains an
unknown outcome until the application idempotency path reconciles it.

The application fixture covers Actor2Actor, SC01 and Rabbit paths. It does not yet
prove executed Server SC01 ingestion/dispatch, FediWatch interoperability, mid-commit
crash recovery, credential revocation during active traffic, or sustained
backpressure. Canonical outbound Target client-outcome tracking and a durable
Actor2Actor lifecycle journal also remain unimplemented; the bounded in-memory
dispatcher replay cache is not restart-safe lifecycle recovery. These remain
separate acceptance gaps even if this fixture passes.

* Native gate

=scripts/test-embedded-router.sh= runs a bounded SBCL driver. It requires the
shared library and a local StarLang checkout supplied by the build; it does not
install tools, download dependencies, start public listeners, or fall back to a
subprocess router. Missing prerequisites fail the command rather than skip.
Use a freshly installed native library for packaging evidence.

The driver must be followed by real Server application and Rabbit integration
gates before claiming end-to-end support. Existing =t/http-api-test.lisp= uses
a no-op =stub-producer= and cannot establish Rabbit publication evidence.

* Application acceptance command

Run =scripts/test-embedded-router.sh --application= inside the supported Server
Nix development environment with =STAR_ROUTER_LIBRARY= and =STAR_LANG_SOURCE=
set to the pinned installed library and StarLang checkout. This requires
=STAR_ROUTER_E2E_ACK_DISPOSABLE=1=, real dedicated loopback CouchDB/RabbitMQ,
and their synthetic fixture credentials. Missing requirements fail, not skip.

=tests/embedded-router-application.py= launches the Lisp Server fixture twice
as separate processes. It uses the generated minimal-operation fixture,
supported authenticated HTTP targets/documents, a real Rabbit target queue,
and real Server Rabbit ingestion. Rabbit duplicate processing waits for actual
consumer acknowledgement counters, followed by independent revision/content
readback. It does not equate broker routing with durable commit.

=tests/embedded-router-application.lisp= starts =star.runtime=, uses the native
CFFI host and a real loopback DEALER, and emits its synthetic message manifest
through the pinned StarLang compiler. The existing StarLang dispatcher owns
accepted/reply/completed/error/cancel/deadline/replay behavior. Trusted fixture
configuration maps an allowlisted CURVE public key to a context authenticated
through the real credential store. Routing identities never grant authority;
the fixture attempts the same identity using an unlisted key. It reconnects
under a different routing identity with the authenticated key.

The workflow provisions only private disposable service containers, records
their image digests and actual Rabbit server version, and removes the owned
containers/credentials. The new fixture selects RabbitMQ =4.3.7-management=
and CouchDB =3.5.3=; those selections are not claims that either image has run.
No production image pin is changed. If full application acceptance fails,
=--rabbit-only= runs the independent Rabbit subset in a fresh fixture database;
that result cannot turn the failed native acceptance green.

=--sc01= selects a separate, explicit legacy fixture using
=tests/embedded-router-sc01.lisp=. A real CURVE DEALER registers the pinned
actor instance, and a real CURVE SUB observes a broker heartbeat before any
HTTP Target is submitted. The Target passes through the existing Server
acceptance path, the SC01 owner queue, and the embedded Nim PUB projection.
The actor sends the canonical generated document as =newDocument= and waits
for the host-settled ACK; replay, forbidden dataset, malformed JSON and wrong
profile checks follow. Authenticated HTTP readback and a fresh Lisp Server
process then verify the stored content and revision. The frame fixture follows
StarRouter's actual =embedded_sc01.py= tests; it introduces no Actor2Actor
cancellation/result semantics or fallback into SC01. No real collector runs.

The exact minimal-operation fixture deliberately omits optional =extensions=.
If the existing readback path adds that field, acceptance fails and records
the separately owned PR #331 prerequisite. Do not normalize the expected
fixture or copy that PR's fix into this transport change.

* Required observed application sequence

Provision a disposable loopback-only Server/CouchDB/Rabbit stack and synthetic
dataset using the repository's existing startup/authentication mechanisms.
Keep credentials in private files. Authenticate =POST /api/v1/targets= using
the supported Target contract in =cli/http-contract-targets.lisp=,
then receive the Target through the embedded router using the canonical actor
codec. Submit the synthetic actor's document through the configured router
ingest adapter; poll =GET /api/v1/documents/:id= with a finite deadline.
Replay exactly the same operation and compare durable content, reject a
conflicting replay, restart the owned Server, and read again. Neither direct
CouchDB inserts nor an HTTP POST echo substitute for this chain.

The Rabbit sibling test observes actual target delivery through the
existing Rabbit route and actual document ingestion through
=documents.ingest.<dtype>=. Preserve broker confirmation and application
commit as separate assertions. Do not transplant the separately owned
readiness-ingestion PR #344 merely to make this branch appear complete.
