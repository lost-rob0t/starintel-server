* Design

** D1. Versioned route shapes (the decision the issue asks to record here)

| operation id | method | registry path      | openapi path            | scopes            | authority |
|--------------+--------+--------------------+-------------------------+-------------------+-----------|
| documents.create | POST | /api/v1/documents       | /api/v1/documents       | documents:write | authenticated |
| documents.bulk.create | POST | /api/v1/documents/bulk | /api/v1/documents/bulk | documents:bulk | authenticated |
| documents.get | GET   | /api/v1/documents/:id | /api/v1/documents/{id} | documents:read | authenticated |
| documents.update | PUT | /api/v1/documents/:id | /api/v1/documents/{id} | documents:write | authenticated |
| documents.delete | DELETE | /api/v1/documents/:id | /api/v1/documents/{id} | documents:delete | authenticated |
| documents.search | GET | /api/v1/documents/search | /api/v1/documents/search | search:read | authenticated |

Rejected alternatives:
- =PUT/POST /api/v1/documents/:id= reuse of =/search= at =/api/v1/search=: that
  path is the public server-owned search; the contracted search keeps caller
  dataset/tenant scoping, so it must be a distinct path
  (=documents.search= → =/api/v1/documents/search=).
- =GET /api/v1/search= for the authenticated search: collides with
  =public.search.get= (different authority and scoping semantics).
- Keeping dtype in the path (=POST /api/v1/documents/:dtype=): canonical v0.9
  documents carry =dtype= in the body; the path dtype is a legacy adapter
  shape. The versioned route validates the body dtype strictly (same
  =validate-document-input= call with no path dtype).

* Adversarial review

1. *Unmapped-route lockout*: adding registry paths without =route-action=
   mappings would 403 every contracted document call (issue #3 failure class).
   Covered by D4 + test 4.
2. *Route shadowing (search vs :id)*: myway is registration-ordered; mounting
   =documents.get= before =documents.search= silently captures
   =GET /api/v1/documents/search= as =:id="search"=. Mitigation: mount search
   first + test 5 asserts order. No other static/:param overlap exists among
   the six paths (bulk is POST-only; search is GET-only; :id routes share one
   static-free namespace).
3. *Legacy drift*: reusing handler internals via parameterized helpers with
   legacy-default labels keeps legacy behavior bit-identical; no legacy route
   definition, mount order, or validation semantics change. =/dataset-size=
   fix deletes only a provably dead definition.
4. *Emission duplication*: =operation-openapi-object= exists in two files (base +
   final override). Changing only one would leave drift; design updates both.
5. *Client generation*: generated wrappers derive from =all-http-operations=;
   adding operations automatically extends =star.api.client=. Existing client
   tests assert >= 16 operations (floor, not ceiling) — safe.
6. *Schema normalization*: new file normalizes its own schemas (targets.create
   precedent loaded after the global pass is NOT copied).
7. *Security*: no new public path; all six operations are bearer-authenticated
   and resource-authorized by the same =authorized-*= pipelines used by the
   hardened legacy routes; audit metadata uses the true versioned route label.
8. *Idempotency/retry*: document create stays accept-then-ingest (queue
   semantics documented in README); update remains compare-and-swap with
   bounded retries inside =upsert-document-update=. No new semantics.
9. *Concurrency*: bulk inline/async split and per-principal quota unchanged;
   async jobs reuse the existing worker pool.
10. *Restart/reload*: =upsert-http-operation= is reload-safe (removes by id
    before append); =mount-http-operation= replaces mounts in place.

No design-invalidating counterexample found. One design revision recorded:
=D3= (query-parameter metadata) was added after the first draft was judged
shape-incomplete for search.
