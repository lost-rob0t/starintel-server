*** load-addon
:PROPERTIES:
:KIND: fn
:PACKAGE: STARINTEL-GSERVER
:END:
#+begin_src common-lisp
(load-addon (STARINTEL-GSERVER::SYSTEM))
#+end_src
Load SYSTEM through ASDF and start its registered StarIntel lifecycle.

This is the intended init.lisp experience:

  (load-addon :starintel-bixby)

Add-ons are trusted operator code, exactly like init.lisp; this is a lifecycle
and packaging boundary, not a sandbox or an authorization boundary. Lifecycle
operations are serialized so load/stop/reload cannot interleave.
*** load-init-file
:PROPERTIES:
:KIND: fn
:PACKAGE: STARINTEL-GSERVER
:END:
#+begin_src common-lisp
(load-init-file (STARINTEL-GSERVER::INIT-PATH))
#+end_src
Load the init file INIT-PATH with error handling.

The file is evaluated in whatever package it declares; the stock
template uses =(in-package :star)= so settings like
=star:*http-api-port*= are directly assignable.  Signals on failure
after logging.
*** main
:PROPERTIES:
:KIND: fn
:PACKAGE: STARINTEL-GSERVER
:END:
Binary entry point; parses argv via clingon and dispatches subcommands.

Subcommands:
- =start= :: run the server runtime loop until interrupted
- =admin= :: administrative utilities
*** register-addon
:PROPERTIES:
:KIND: fn
:PACKAGE: STARINTEL-GSERVER
:END:
#+begin_src common-lisp
(register-addon (STARINTEL-GSERVER::NAME &KEY STARINTEL-GSERVER::SYSTEM
 STARINTEL-GSERVER::START STARINTEL-GSERVER::STOP))
#+end_src
Register a trusted StarIntel add-on lifecycle.

Add-on systems call this while ASDF loads them. START and STOP must be
zero-argument functions. Registration is metadata only; it does not start the
add-on and therefore remains safe to repeat during ASDF reload.
*** reload-addon
:PROPERTIES:
:KIND: fn
:PACKAGE: STARINTEL-GSERVER
:END:
#+begin_src common-lisp
(reload-addon (STARINTEL-GSERVER::SYSTEM))
#+end_src
Reload one add-on transactionally at the lifecycle boundary.

The old START/STOP function objects are retained until the replacement starts.
If loading or starting the replacement fails, the old definition and START
hook are restored when possible. ASDF dependencies own dependency ordering;
START/STOP hooks must not recursively invoke add-on lifecycle operations.
*** repl/main
:PROPERTIES:
:KIND: fn
:PACKAGE: STARINTEL-GSERVER
:END:
#+begin_src common-lisp
(repl/main (STARINTEL-GSERVER::INIT-FILE))
#+end_src
Load and start the server from the REPL.

Unlike =main= this returns after the runtime stops instead of exiting
the image, so callers can inspect state afterwards.  INIT-FILE is the
init script path, usually =./init.lisp=.
*** safe-load-init
:PROPERTIES:
:KIND: fn
:PACKAGE: STARINTEL-GSERVER
:END:
#+begin_src common-lisp
(safe-load-init (STARINTEL-GSERVER::INIT-PATH))
#+end_src
Load INIT-PATH, creating it first if it does not exist yet.

Returns T on success, signals an error on failure.  This is the
idempotent entry point used by the runtime startup.
