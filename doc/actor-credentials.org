#+title: Actor account credentials add-on

The optional =starintel-actor-credentials= add-on binds an actor, account, and
credential type to an operator-owned provider. A target carries only an
=account_id= selector. The secret stays out of target documents, RabbitMQ,
manifests, and source control.

* Configure
Load the add-on in the private server init file and register an account:

#+begin_src lisp
(star:load-addon :starintel-actor-credentials)
(star.actor-credentials:register-credential
 "discord-watch" "bot-east" "bot-token"
 (lambda () (uiop:getenv "STARINTEL_DISCORD_BOT_EAST_TOKEN")))
#+end_src

An authorized external actor calls =actor-credentials.resolve= through the
published client manifest. The =POST /api/v1/actor-credentials/resolve= body is
={"actor":"discord-watch","account":"bot-east","credential_type":"bot-token"}=.
It returns the credential as a JSON value (string, object, or array)
over the authenticated server connection with =Cache-Control: no-store=.
Use another type such as =oauth=, =api-key=, or =cookie-jar= with the same
=register-credential= call. The provider may return a JSON object when a
platform needs multiple values; the actor decides how to interpret that type.

The actor's API key must have principal type =service= and these scopes:
=actor-credentials:read=, =actor:discord-watch=, =account:bot-east=, and
=credential-type:bot-token=. All resource scopes are required. The server applies authorization before it
calls the provider. An unavailable account or provider produces a generic
error with no secret or provider exception text.

Provision the provider and actor API key through private operator
configuration. Do not put provider credentials in targets, command arguments,
logs, or repository files. Rotate a provider by changing the private source;
the next resolve call reads its current value.
